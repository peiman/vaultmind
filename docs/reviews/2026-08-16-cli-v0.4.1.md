# VaultMind CLI review — v0.4.1

**Date:** 2026-08-16
**Reviewed revision:** `a74236e` (`chore(release): v0.4.1` on `main`)
**Kind:** investigation, not a patch series
**Threat model:** a local CLI that indexes and queries markdown vaults. The
realistic attacker is an untrusted or collaborator-supplied vault (cloned repo,
shared folder, malicious note), plus agent/script consumers that treat exit
code and `--json` envelopes as a contract. This is not a network service.

No product behavior was changed for this review. Several findings look
fixable; they are documented rather than rewritten so the tradeoffs stay
visible.

---

## Scope and method

Read the public tree only. No private identity vault, no credentials, no
live enroll against a relay.

Worked from code, tests, and docs — not from a single hypothesized root
cause. Three parallel passes (security, correctness/contracts, architecture/UX)
were then re-checked against the files cited below.

Looked at: vault discovery and open paths, index/rebuild/incremental/embed,
FTS and store upserts, doctor/status/heal, ask/search/note/memory, hooks
install and embedded scripts, episode capture, export/telemetry, embedding
download, identity signer (DEV-INTERIM), envelope/exit contract, and the
docs that agents actually read (`README.md`, `docs/AGENT_USAGE.md`,
`SECURITY.md`, `AGENTS.md`).

v0.4.1 itself was a review pass over v0.4.0 (episode `--output-dir`,
collision reporting, desk `created` dates). This document starts from that
baseline and does not re-litigate those fixes.

---

## Overall quality

This is a careful CLI. The project has already named and fixed the failure
classes that usually sink tools like this: silent wrong-vault answers,
guessed paths that create `.vaultmind/` as a side effect, JSON envelopes
that say `error` while the process exits 0, and notes that vanish from the
index with no message. Those fixes are real, tested, and documented in
place.

What remains is incomplete application of those same standards, plus a
small set of vault-boundary holes on *derived* paths (config `db_path`,
templates, symlinks) that write-path guards do not cover. Nothing in this
pass looks like a critical remote issue or like private vault data shipping
in the public repo.

## What's solid

1. **Guessed-vault fail-closed (read path).**
   `OpenVaultDBOrWriteErr` refuses to open a non-vault directory when the
   caller did not name one, and will not create `.vaultmind/index.db` as a
   side effect of `ask` / `search` / `note get` / `memory *`. The comment at
   `internal/cmdutil/helpers.go:183-191` is the spec; tests in
   `internal/cmdutil/helpers_test.go` lock it.

2. **`$HOME` is never auto-selected.** Walk-up discovery stops before the
   home directory (`cmd/vault_discovery.go`). Explicit `--vault` or
   `VAULTMIND_VAULT` still works. Tests cover the regression.

3. **Write-path vault confinement.** Note create, frontmatter mutators, plan
   apply, and dataview render reject targets that escape the vault root
   (`internal/mutation/mutator.go`, `cmd/note_create.go`,
   `internal/plan/executor.go`, `internal/marker/render.go`).

4. **FTS and SQL.** Search uses parameterized `MATCH ?` plus
   `sanitizeFTSQuery` quoting (`internal/index/fts.go`). Dynamic table names
   in the store are a fixed const list.

5. **Hook install.** Scripts come from an embedded FS by exact basename
   (traversal rejected in tests). Vault paths in generated settings are
   single-quoted. Conflict detection requires `--force`. Merge is additive.

6. **Episode cursors.** Cursor keys are restricted to a safe charset;
   output-dir is hashed into the key so two vaults do not share a cursor
   (`internal/episode/cursor.go`, `vaultScopedCursorKey`).

7. **JSON envelope versioning.** `schema_version: "v1"` on every envelope;
   consumer structs in `cmd/contract_*_test.go` are decoupled from internals.
   Vault-not-found `--json` now returns `ErrAlreadyWritten` through to
   `main.go` (exit 1) — `cmd/exit_contract_test.go` states why that matters.

8. **Open-core boundary.** No `vaultmind-identity/` in the repo. The shipped
   example is the fictional `examples/ada-vault`. `.gitignore` expects local
   persona/research vaults. Episodes are excluded from default indexing
   (when the default exclude list is in force).

9. **Identity signer (DEV-INTERIM) is honest.** `internal/identity/signer`
   documents that same-UID is not a privilege boundary, refuses an empty
   UID allowlist, refuses to hijack a live socket, and refuses a
   group/world-readable key file.

10. **Doctor HTTP client** for local probes is loopback-pinned, redirect-refusing,
    and size-capped. Model download URLs are fixed HuggingFace paths, not
    user-controlled.

11. **Rebuild duplicate-ID handling** is explicit: first file wins, counted,
    tested (`internal/index/duplicate_id_test.go`). Full re-embed after purge
    fails loud. Index `ErrorDetails` are printed in human output (issue #40).

12. **Config keys in production `cmd/`** go through `config.Key*` constants.

## Findings

### High

#### H1. Incremental index lets a duplicate ID steal the row — and the next run steals it back

**Area:** `internal/index/indexer.go` (`Incremental`, ~640–724),
`internal/index/store.go` (`upsertNote`, 219–240)

**What happens.** `Rebuild` keeps an in-memory `seenIDs` map and skips the
second domain note with the same `id` (first file wins). `Incremental` has
no such guard. It calls `StoreNote` → `ON CONFLICT(id) DO UPDATE SET path=…`.

Because `NoteHashes()` is keyed by *path*, the overwritten file disappears
from the stored-path set. The next incremental pass treats that file as new
and upserts again. Two files sharing an id therefore **flip-flop ownership
on every `vaultmind index`**.

Doctor cannot see this. `notes.id` is unique, so

```sql
SELECT COUNT(*) FROM (SELECT id FROM notes GROUP BY id HAVING COUNT(*) > 1)
```

in `internal/query/doctor.go:293` is structurally zero. The comment there
already says “should be 0 with UNIQUE constraint, but check anyway.”
Rebuild’s `DuplicateIDs` counter never runs on the incremental path.

**Risk.** Retrieval, `ask`, `note get`, and `memory pack` follow the id.
The body and path behind that id change without a warning. A vault that
looks healthy (`doctor` reports 0 duplicate ids) is oscillating.

**Recommended fix.** Reuse Rebuild’s `seenIDs` (or a `SELECT path FROM notes
WHERE id=?` before upsert) in `Incremental`. Increment `DuplicateIDs`, skip
the loser, warn. Add a test that two same-id files do *not* swap path
across two incremental runs. Consider a doctor check that is
path-collision-aware (same id, two files on disk) rather than
row-duplicate-aware.

#### H2. `--json` error envelopes still exit 0 on several agent-facing commands

**Area:** `internal/query/note.go:30–47`, `internal/query/links.go:119–123`,
`cmd/experiment_report.go:36–53`, `cmd/index.go:63–75`, `cmd/apply.go:46–85`,
`cmd/frontmatter_helpers.go:53–59`, and every other `return
cmdutil.WriteJSONError(...)` site.

**What happens.** `cmd/exit_contract_test.go` documents the exact bug:
envelope `status: "error"` with process exit 0 breaks
`vaultmind … --json || handle_failure`. Vault-*open* failures were fixed
via `ErrAlreadyWritten` → `main.go` exit 1.

The fix was not applied to command-level failures:

| Call | Envelope | Process |
|------|----------|---------|
| `note get missing-id --json` | `not_found` | exit 0 (`cmd/clirunners_test.go:47` asserts this) |
| `note get` ambiguous title `--json` | `ambiguous_resolution` | exit 0 |
| `memory links` unresolved `--json` | `resolution_failed` | exit 0 |
| `index` missing vault / bad config `--json` | `vault_not_found` / `config_error` | exit 0 (`WriteJSONError` returns the encode error, which is nil) |
| `apply` bad plan `--json` | `read_error` / `parse_error` | exit 0 |
| `experiment report` missing db/name `--json` | `db_error` / `not_found` | exit 0 |
| frontmatter mutation errors `--json` | mutation code | exit 0 |

Text-mode `note get` for a missing id also returns nil
(`fmt.Fprintf` of “No note found”), so `||` handlers fail there too.

**Risk.** Agent hooks and CI treat the command as success. This is the
class of silent failure the v0.3/v0.4 exit-contract work was written to
end.

**Recommended fix.** After writing an error envelope, return
`cmdutil.ErrAlreadyWritten` (or a typed `envelope.StatusError`). Extend
`TestJSONErrorMustNotReportSuccess` beyond vault-not-found: missing note,
ambiguous resolve, bad plan, index config error. Update the few tests that
currently require `NoError` on those paths. Decide explicitly whether
text-mode “not found” is exit 1 (recommended for scripts) or stay 0 with
docs.

#### H3. `vaultmind index` still creates a vault on a guessed path

**Area:** `cmd/index.go:61–80`, `internal/index/db.go:25–31`

**What happens.** Read commands go through `OpenVaultDBOrWriteErr`, which
refuses a guessed non-vault. `runIndex` does not. It `Stat`s the
discovered path (cwd if walk-up found nothing), `LoadConfig` returns
defaults when `.vaultmind/config.yaml` is absent, and `index.Open`
`MkdirAll`s `.vaultmind/` then creates `index.db`.

That is the self-propagating mistake described at
`internal/cmdutil/helpers.go:183-191` and re-fixed for `arc candidates` in
`cmd/arc_candidates.go:130-141`. `index` is the command that actually
writes the marker every later walk-up will find.

**Risk.** `vaultmind index` in a random checkout, a monorepo package, or a
temp dir silently promotes that directory to a vault. Later `ask`/`search`
from a child directory hit the accidental index. `vaultmind init` is the
explicit create path; index should not also be one on a guess.

**Recommended fix.** If the vault was not named (`--vault` /
`VAULTMIND_VAULT`) and the path has no `.vaultmind/`, fail with the same
`errGuessedNonVault` message. Named `--vault <dir>` can stay permissive
(create-on-index is reasonable when the operator pointed at a directory).
Add a regression test next to the existing guessed-vault tests.

### Medium

#### M1. Vault-relative derived paths are not confined

**Area:** `internal/cmdutil/helpers.go:69`, `cmd/index.go:79`,
`internal/vault/config.go` (`Index.DBPath` — no validation),
`cmd/note_create.go:99`, `internal/template/process.go:112`,
`internal/marker/render.go:274-276`, `internal/index/indexer.go:603-606`

**What happens.** Write targets are confined. These reads/opens are not:

- `db_path` from config is `filepath.Join(vaultPath, cfg.Index.DBPath)`.
  `Join` discards the vault prefix when `db_path` is absolute, and
  `../` walks out. `index.Open` then creates parent directories.
- Type-registry `template:` is joined the same way and `ReadFile`d.
- `LoadSectionTemplate` joins `noteType` and `sectionKey` from
  frontmatter into `.vaultmind/sections/{type}/{key}.md` with no
  charset check and no vault-prefix check. `noteType=../../../etc`
  reads outside the vault (`.md` suffix is a minor limit).
- `Indexer.IndexFile(relPath)` joins without a prefix check. Current
  callers pass already-validated paths; the function itself does not
  enforce that.

**Risk.** Opening a third-party vault (or rendering a collaborator’s
note) can create/open a SQLite file outside the vault, or read arbitrary
files the OS user can read. Local operators can already write anywhere;
the issue is *untrusted vault content/config*.

**Recommended fix.** One helper: after `Clean`, require the result to
stay under the vault root (the same `HasPrefix(cleanAbs, cleanVault+sep)`
pattern). Reject absolute and `..` `db_path` / `template` at config load.
Restrict `noteType` / `sectionKey` to `^[A-Za-z0-9_-]+$`. Put the same
guard inside `IndexFile`.

#### M2. Index and doctor follow symlinks out of the vault

**Area:** `internal/vault/scanner.go:33-85`,
`internal/index/indexer.go:451` and `674`,
`internal/query/doctor.go:479-483`

**What happens.** `filepath.WalkDir` does not descend into directory
symlinks, but a *file* symlink named `*.md` is collected. `os.ReadFile`
follows it. A note `secrets.md` → `~/.ssh/id_rsa` (or any readable file)
is hashed, parsed, stored in FTS, embedded, returned by `note get` /
`ask`, and exported.

**Risk.** Untrusted vault content becomes a read primitive against the
operator’s filesystem. Indexed secret material then lives in
`.vaultmind/index.db`.

**Recommended fix.** `Lstat` / `O_NOFOLLOW` before read; skip or error on
symlinks during scan. Add a scanner test with a symlink pointing outside
the temp vault.

#### M3. Doctor and `vault status` advertise an index-freshness field they never compute

**Area:** `internal/query/doctor.go:228-231`,
`internal/query/status.go:30-41` and `37-66`

**What happens.** Both structs initialize `IndexStatus: "current"` and
never update it. `StatusResult.IndexStale` is declared and stays false.
`DoctorResult.Issues.StaleIndex` *is* populated from content-hash drift,
so JSON consumers that look at `issues.stale_index` are fine; consumers
that look at `index_status` are not.

`TestDoctor_IndexStatusIsAlwaysPopulated` only asserts non-empty.

**Risk.** Automation that branches on `index_status == "current"` ignores
a stale index. The field is worse than absent — it is a constant success
signal.

**Recommended fix.** Set `IndexStatus` from `StaleIndex` (and from
deleted-on-disk, see M4). Populate `VaultStatus.IndexStale`. Or deprecate
`index_status` in favor of `issues.stale_index` and document it.

#### M4. Deleted-on-disk notes are invisible to doctor drift

**Area:** `internal/query/doctor.go:479-484`,
`internal/query/doctor_drift_test.go:140-156`

**What happens.** `DetectContentDrift` `ReadFile`s each indexed domain
note and `continue`s on any read error. The test names this
`TestDetectContentDrift_DeletedFileSilent` and asserts empty drifts.

**Risk.** A deleted file leaves a ghost row until the next incremental
orphan sweep. `doctor` reports a current, healthy vault. Incremental
index *does* delete orphans — doctor is the command that is supposed to
say “run index.”

**Recommended fix.** Treat `os.IsNotExist` as its own issue
(`orphaned_index_entry` or count toward `stale_index`). Keep “do not
abort the run” (the test’s other assertion).

#### M5. Telemetry copy, default, and write path disagree

**Area:** `README.md:116-118`,
`internal/config/commands/experiments_config.go:9`,
`internal/experiment/telemetry.go:12-18`,
`cmd/root.go:266-291`

**What happens.** README: sharing is opt-in, sanitized, no query text,
**off by default**. Code: default is `"anonymous"`; anonymous and full
use the **same local write path** (query text, vault path, note ids into
`~/.local/share/vaultmind/experiments.db`). Sanitization exists at
*export* time only. The first-run prompt runs only when
`telemetry == ""`, which the default prevents, so most installs never
see it.

**Risk.** Privacy expectation mismatch. Not a remote leak today (no
uploader). Local disk holds full query text under a setting named
“anonymous.”

**Recommended fix.** Align the three surfaces. Either default to `off`
and show the prompt when unset, or keep local-anonymous and change the
README to: “local event log is on by default; sharing is opt-in at
export; anonymous export strips query text and paths.” If the name
“anonymous” is kept, redact at write time or stop storing `query_text` /
`vault_path` for that tier.

#### M6. Partial index / embed failure is exit 0; store failures are Debug

**Area:** `cmd/index.go:90-105`, `cmd/index.go:196-205` (human errors
printed, then success), `internal/index/indexer.go:921-922`, `958`, `971`

**What happens.** `Incremental`/`Rebuild` return `nil` when individual
files fail; `result.Errors` and `ErrorDetails` are filled and printed.
`PostIndexWarnings` and `DuplicateIDs` are JSON-only — human
`formatIndexResult` does not print them. Embed batch failures `Warn`;
per-note store and commit failures `Debug` (default console is INFO),
then increment `embed_errors` and continue. `--full` embed is the one
path that fails loud after a purge.

**Risk.** Hooks that run `vaultmind index --embed` after edits treat a
partial graph or missing embeddings as success. Semantic recall degrades
until someone reads counts or runs `doctor`.

**Recommended fix.** Promote store/commit failures to `Warn`. Print
`post_index_warnings` and `duplicate_ids` in human output. Add `--strict`
(or non-zero exit when `Errors > 0`) so agents can opt into fail-closed
without surprising existing interactive use.

#### M7. BGE-M3 download trusts presence, not integrity

**Area:** `internal/embedding/download.go`

**What happens.** Files are fetched from
`https://huggingface.co/BAAI/bge-m3/resolve/main/…` with a 30-minute
client, atomic `.tmp`+rename, and **no checksum, size check, or pinned
revision**. A later run that sees the dest file skips it. A truncated or
substituted object that closed with HTTP 200 is cached forever. Default
`http.Client` follows redirects.

**Risk.** Supply-chain / CDN truncation: embeddings silently wrong, or a
redirected payload executed as an ONNX model. Local CLI, HTTPS, fixed
host — not remote RCE by query text — but 2.2 GB of unverified weights
is a large trust grant.

**Recommended fix.** Pin a revision SHA, store expected SHA-256 per
file, verify before rename, re-download on mismatch. Document the
accepted risk until then. The embedding package is excluded from the
coverage gate; add at least a fake-server hash-mismatch test.

#### M8. Default scan excludes omit `.vaultmind`; init templates include it

**Area:** `internal/vault/config.go:68`,
`internal/initvault/templates/.vaultmind/config.yaml:6`,
`examples/ada-vault/.vaultmind/config.yaml:6`

**What happens.** Scaffolded and example vaults exclude `.vaultmind`.
`LoadConfig` defaults (no config file, or the coded default list) do
not. Dataview section templates are `.md` files under
`.vaultmind/sections/`. A no-config vault, or a config that relies on
coded defaults, indexes those templates as notes.

**Risk.** Template boilerplate pollutes retrieval. Combined with M2, a
symlink dropped under `.vaultmind/` is also indexed.

**Recommended fix.** Add `.vaultmind` to `defaultExcludes` and to
`TestLoadConfig_DefaultExcludes`. Keep it in the init template.

**Area:** `cmd/help_template.go:155`, many command help strings,

Root help says “see vaultmind-identity/ in the repo.” That directory is

**keyword**. Auto/hybrid is `ask`’s behavior.

**Recommended fix.** Point help at `examples/ada-vault` and

#### L3. Hook defaults assume a layout the public repo does not ship

**Area:** `internal/hookscripts/load-persona.sh:24`,
`internal/hookscripts/capture-episode.sh`

Without `hooks install --vault`, SessionStart looks at
`$PROJECT_DIR/vaultmind-identity` and a second “research” vault at
`vaultmind-vault`. Sidecar logs under `~/.vaultmind/` include
`vault_path` and, in other scripts, file paths / bash targets.

**Risk.** Empty persona (fail-loud in current scripts — good) or the
wrong local folder if the adopter created those names for something
else. Logs are a local-disclosure issue on a shared machine.

**Recommended fix.** Document `init` + `hooks install --vault … --merge`
as mandatory before relying on hooks. Consider failing if the default
path does not exist rather than querying it. Redact paths in sidecar
logs; `mkdir` the log dir at `0700`.

#### L4. Episode `--output-dir` is not vault-bound; default is CWD-relative

**Area:** `cmd/episode.go` (default `vaultmind-identity/episodes`),
`internal/episode/capture.go:46-50`

By design this writes outside the vault. Default is relative to **cwd**,
not `--vault`. Export `--output` likewise `os.Create`s (truncates) any
path.

**Recommended fix.** Resolve the default under `--vault` (or require an
explicit dir). Refuse to truncate `--output` without `--force`. Vault
confinement is optional here if the flag stays “write wherever,” but the
default should not create `./vaultmind-identity/` in a random cwd.

#### L6. `ask --quiet-on-no-match` empties text stdout

**Area:** `cmd/ask.go:165-178`

Used by recall hooks. Text mode returns nil with empty stdout, which

#### L7. Architecture drift in `cmd/`

ADR-001 wants ≤30-line wiring. The validator **warns at 80 lines** and
does not fail CI (`.ckeletin/scripts/validate-command-patterns.sh`).
`cmd/doctor.go` (~546), `cmd/index.go` (~262), `cmd/episode.go` (~266),
`cmd/export.go` (~221), `cmd/ask.go` (~209) hold real logic.

Not a user-facing bug. It will keep making H2-style exit-contract fixes
harder (logic and envelope writes live in too many layers).

**Recommended fix.** Move remaining diagnosis/format/preview bodies into
`internal/`. Optionally fail the validator at a ratchet (e.g. 120 → 80)
instead of warn-only.

## Test gaps (failure paths)

Well covered today: guessed-vault fail-closed, `$HOME` guard, write-path
traversal, rebuild duplicate ids, anonymous *export* sanitization,
episode bad output-dir / collisions, vault-not-found `--json` exit 1,
ask text-mode contract.

Missing or inverted:

- Incremental duplicate-id flip-flop (H1) — only Rebuild is tested.
- `--json` exit ≠ 0 for not-found / ambiguous / bad plan / index config (H2)
  — several tests **require** exit 0.
- `vaultmind index` in a non-vault cwd (H3).
- `db_path` / template / section-type escape (M1).
- Symlink-to-outside-vault (M2).
- `index_status` actually becoming `"stale"` (M3).
- Deleted file as a doctor issue (M4) — current test forbids it.
- Model download hash mismatch (M7).
- Default exclude includes `.vaultmind` (M8).
- `export --output` overwrite of an existing file.
- `memory pack` (canonical) contract case (L8).
- Hook sidecar logs do not contain note bodies (they should not; unverified).

## Recommended work order

1. **H1** — incremental duplicate-id skip + test (correctness; small surface).
2. **H2** — `ErrAlreadyWritten` on remaining error-envelope returns; extend
   exit-contract tests (agent-facing; behavior change for anyone relying on
   exit 0).
3. **H3** — guessed-path guard on `index` (same helper the read path uses).
4. **M1 + M2** — shared vault-confine helper + symlink skip (untrusted vault).
5. **M5 + L1 + L2** — docs/defaults honesty (README, SECURITY, help, telemetry).
6. **M3 + M4 + M6 + M8** — doctor/index signals that match reality.
7. **M7** — pin and hash model files when someone next touches download.

Do not squash these into one commit if you implement them. H2 in
particular should be reviewable as an exit-code contract change.

## What this review did not change

No code, defaults, or contracts were modified. The incremental-id and
exit-code items are high-severity and relatively local, but both change
observable behavior and need their own tests. They are left as findings.

Nothing in this document is a private vault path, a credential, or a
session transcript.
